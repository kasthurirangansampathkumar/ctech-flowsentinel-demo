Solution Description

SentinelView AI is a GCP-native, AI-first on-call automation framework for Data Engineering teams. It sits on top of an organization's existing pipeline stack — Cloud Composer/Airflow, BigQuery, GCS, Pub/Sub — and turns the four things a human on-call engineer normally does by hand into instant, AI-driven steps: investigate, triage, diagnose, and draft a fix. A human is needed for exactly one thing: approve, or don't.

Every incident — a stalled DAG, a missed SLA, schema drift, a corrupted table — is automatically classified, routed to the right automation tier, diagnosed by a purpose-built Gemini agent, and either fixed autonomously or handed to the on-call engineer as a one-click-approve recommendation, with a real GitHub Issue/PR trail the whole way through.

It is built as a reusable framework, not a one-off script — the agent logic is fully decoupled from any one client's pipelines, so a working engagement becomes a fast-start template for the next.

Key Capabilities

Detection & Classification

  • Issue Segment Agent classifies free-text incidents into 14 categories in seconds, with a confidence score.
  • Works from vendor incident text or a synced GitHub Issue — no proprietary format required.

Automation Tiers

  • Autonomous — agent resolves end-to-end, no human step.
  • AI-Assisted — agent diagnoses and drafts the fix; one-click human approval.
  • Advisory — credential/IAM changes are never auto-remediated, by design.

Grounded Agents

  • 13 agents, one per failure family — Source Feed Sentinel, API Health, Orchestration Watchdog, Query Doctor, Data Observability, Infra Health, Capacity Forecaster, Pace Predictor, Backfill, Schema Drift, DQ Check, and the Ops Read-Out summarizer.
  • Each grounded in a real check (GCS file existence, BigQuery row-count comparison, live Composer/Logging status) before Gemini narrates or decides.

Native Integration

  • Every ticket mirrors to a real GitHub Issue; approved fixes become real PRs.
  • Demo Mode / Production Mode toggle — one dashboard, same code, safely demoable or fully live.
  • CI/CD: DAG changes on GitHub auto-validate and auto-deploy to Composer via Workload Identity Federation.

Value Proposition

  • Collapses the on-call night — three of four manual steps done instantly; only a one-click approval remains for anything not fully autonomous.

  • AI-first, not AI-bolted-on — every agent reasons over real, live data first; this is decision automation with a verifiable trail, not a guessing chatbot.

  • Human judgment only where it matters — routine failures never reach a person; judgment-heavy or security-sensitive ones always do.

  • No new tools to adopt — tickets are real GitHub Issues, fixes are real PRs, on the workflow teams already use.

  • Replicable, not bespoke — the agent framework is client-agnostic; a demo in one engagement is a fast-start template for the next.

Key Challenges Addressed

  • On-call burnoutManual cross-referencing across three or four systems at all hours, for every incident regardless of severity.
  • Inconsistent responseQuality depends on who's on call; an agent applies the same diagnostic logic every time.
  • Silent data failuresA pipeline reports "success" while the data is wrong — the hardest failure mode to catch by hand.
  • Vendor dependency riskFeed delays, schema drift, and API instability sit outside DE's control but land on DE's on-call plate.
  • Slow root causeManually reading logs and query history is the single biggest time sink in an incident.
  • Loss-of-control objectionAdvisory tier and mandatory approval for AI-Assisted fixes answer "let AI touch prod" by design.
